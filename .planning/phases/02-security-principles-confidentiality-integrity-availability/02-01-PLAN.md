<threat_model>
## Threat Model

### Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Browser client | Untrusted request origin and file source | Upload bytes, file metadata, object access requests |
| Next.js server | Enforcement boundary for storage policy | Encryption mode, checksum policy, signed URL issuance |
| S3 / MinIO storage | Durable object store with recovery expectations | Encrypted video objects, checksums, version history, backups |
| Backup / replication target | Disaster recovery boundary | Copies of object data and metadata |

### Threats and Controls

| Threat | Risk | Control |
|--------|------|---------|
| Public object exposure | Confidential media leaks without authorization | Keep objects private, issue only signed URLs, and never expose raw bucket URLs |
| Weak or absent encryption | Data at rest can be read if storage is compromised | Use provider-managed encryption defaults in production |
| Corrupted upload or tampered data | Viewers receive altered media or metadata | Use checksum-aware validation and persist integrity metadata |
| Accidental overwrite or delete | Video assets disappear permanently | Require versioning, backup, or replication posture for recovery |
| Regional outage or storage failure | Authorized users lose access | Document and plan for backup or replication recovery |

### Security Decisions

- Provider-managed encryption is the baseline for production object storage.
- Checksums are the integrity mechanism, not `ETag` alone.
- Availability is addressed through versioning, backup, and replication posture.
- The same policy must apply to both S3 and MinIO adapters so environments stay aligned.
</threat_model>
